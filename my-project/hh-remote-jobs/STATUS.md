**КРИТИЧНАЯ НАХОДКА 2026-07-30/08-04 — источник данных:**
Официальный REST API (`api.hh.ru`) заблокирован DDoS-Guard'ом с этой сети —
403 на любой User-Agent (проверено `curl`, ответ содержит `server: ddos-guard`).
Обычный HTML-поиск (`hh.ru/search/vacancy`) тоже не отдаёт реальную выдачу
не-браузерным клиентам. Рабочий канал — **RSS-фид поиска**
(`hh.ru/search/vacancy/rss?text=...&area=...&schedule=...`), который отдаёт
настоящие вакансии (title, company, salary, регион, ссылка), но со строгим
анти-бот лимитом частоты запросов:
- Несколько запросов подряд без паузы → пустой `<doc/>` вместо `<rss>` с
  айтемами (не ошибка HTTP, просто 0 items — легко спутать с "нет вакансий").
- При продолжении накачки — полная блокировка `HTTP 451` на какое-то время
  (проверено: 10 минут было мало, 20+ минут восстановило доступ).
- `REQUEST_DELAY = 15` секунд между запросами в `hh_client.py`, плюс retry
  с бэкоффом 25с при пустом ответе (`MAX_RETRIES_ON_EMPTY=2`) — с этими
  настройками полный прогон (34 ключевых слова × 2 региона = 68 запросов)
  занимает ~20 минут и проходит без единой блокировки.
- **Не гонять ручные curl/python-тесты вплотную друг к другу** — именно
  так словили 451 при первой попытке 2026-08-04. Если нужно проверить
  клиент вручную — делать РОВНО ОДИН запрос и ждать минимум 20 секунд
  перед следующим, а лучше вообще не тестировать вручную, полагаться на
  реальный прогон.

**Ограничения текущей реализации:**
- RSS отдаёт только заголовок + краткое summary (компания/регион/зарплата
  из текста CDATA), НЕ полное описание вакансии — навыки матчатся против
  этого summary, а не полного текста вакансии (в отличие от hh-jobs
  Ташкент, где парсер докачивает detail-страницу для каждой новой
  вакансии). Детальная страница (`hh.ru/vacancy/{id}`) тоже словила 451
  при тесте — возможно тоже под защитой, не проверено с должной паузой.
  Если качество скоринга окажется низким — попробовать аккуратно (с той
  же паузой 15-20с) добавить fetch детальной страницы для новых вакансий.
- `schedule=remote` фильтр в RSS не до конца проверен на корректность —
  несколько тестов с узкими запросами дали 0 items, но не разобрано,
  реально ли рынок пуст или фильтр работает не так как ожидалось. Стоит
  сравнить count с/без `schedule=remote` на широком запросе в спокойном
  режиме (без риска повторной блокировки).
