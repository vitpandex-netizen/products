## 🏷️ 2. Схема версионирования (Semantic Versioning 2.0.0)

Релизы нумеруются по стандарту `vMAJOR.MINOR.PATCH`:

- **MAJOR (v1.0.0 $\to$ v2.0.0):**
  - Несовместимые изменения схемы базы данных (миграции SQLite/PostgreSQL без обратной совместимости).
  - Глобальный рефакторинг архитектуры или смена базового фреймворка.
- **MINOR (v1.0.0 $\to$ v1.1.0):**
  - Добавление новой функциональности с сохранением обратной совместимости:
    - Новые вкладки в TMA (например, система закладок «Избранное»).
    - Персональные push-уведомления по фильтрам кандидата.
    - Подключение новых источников вакансий (LinkedIn, HeadHunter API v2).
- **PATCH (v1.0.0 $\to$ v1.0.1):**
  - Исправление обнаруженных ошибок и багфиксы (например, TASK-005 с `published_at`).
  - Оптимизация производительности SQL-запросов и рендеринга.
  - Улучшение текстов, стилей или обновление библиотек безопасности.

## 🚦 3. Ворота качества (Release Quality Gates)

Перед выкаткой любого релиза на боевой **US Server** изменение обязано пройти 5 рубежей контроля:

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  GATE 1: СИНТАКС│ ──► │  GATE 2: ИБ     │ ──► │  GATE 3: РЕВЬЮ  │ ──► │  GATE 4: СМОУК  │ ──► │  GATE 5: QA     │
│  Linter & Build │     │  Audit Grade A  │     │  Triad Consilium│     │  Deploy & Curl  │     │  Sign-off & DoD │
└─────────────────┘     └─────────────────┘     └─────────────────┘     └─────────────────┘     └─────────────────┘
```

1. **Gate 1: Синтаксис и валидация кода:**
   - Компиляция Python: `python3 -m py_compile ...` (0 ошибок).
   - Линтинг и проверка типов.
2. **Gate 2: Аудит информационной безопасности:**
   - Запуск `python3 ~/.claude/skills/audit/audit.py <path>`.
   - Обязательный критерий допуска: **Grade A** (0 Critical, 0 High).
3. **Gate 3: Рецензирование Триады (Code Review Gate):**
   - Проверка изменений вторым агентом Триады.
   - Фиксация в [`~/dev/TRIAD_SYNC.md`](file:///Users/vitaliyr/dev/TRIAD_SYNC.md).
4. **Gate 4: Автоматизированный Smoke-тест на сервере:**
   - Проверка статуса systemd: `systemctl is-active uzjobs-tma.service hhjob-bot.service`.
   - Проверка эндпоинтов: HTTP 403 при запросе без авторизации, HTTP 200 при валидном токене.
5. **Gate 5: Приёмка QA (Quality Assurance Sign-off):**
   - Проверка соответствия критериям Definition of Done (DoD) из бэклога.
   - Закрытие тикета в [`~/dev/BACKLOG.md`](file:///Users/vitaliyr/dev/BACKLOG.md).

## 🔄 4. Регламент развёртывания (Deployment Flow)

1. **Разработка на Mac (`100.89.205.45`):**
   - Код пишется и проверяется локально.
   - Коммит с осмысленным описанием по стандарту Conventional Commits:
     `feat(tma): ...`, `fix(bot): ...`, `refactor(auth): ...`.
2. **Доставка на US Server (`100.84.223.96`):**
   - Доставка через Git-репозиторий (`vitpandex-netizen/products`).
   - Применение миграций базы данных (если есть).
3. **Перезапуск служб и валидация:**
   ```bash
   sudo systemctl restart uzjobs-tma.service hhjob-bot.service
   systemctl status uzjobs-tma.service hhjob-bot.service --no-pager
   ```
4. **Регламент отката (Rollback Policy):**
   - В случае сбоя или выявления критического бага (P0) после релиза:
     1. Мгновенный откат службы на предыдущий стабильный коммит/тег в Git: `git checkout <prev-tag>`.
     2. Перезапуск служб `systemctl restart ...`.
     3. Занесение инцидента в бэклог с наивысшим приоритетом P0.
