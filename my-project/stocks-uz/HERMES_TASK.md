# HERMES: Stocks-UZ — MVP (Фаза 1: один тикер + разведка источника)

Проект: `/Volumes/External/dev/my-project/stocks-uz/`

## Контекст

Мониторинг акций UZSE (Республиканская фондовая биржа «Тошкент»). **Без
бюджета, без автоматических сделок** — только сбор данных, анализ и
уведомления. Долгосрочный этим и отличается от hh-jobs/hh-remote-jobs:
здесь не "найти вакансию сегодня", а копить историю цен по одному тикеру,
постепенно расширяясь на топ-10 из 56 доступных.

Стартовый тикер: **HMKB** (Хамкорбанк).

Полный список 56 тикеров UZSE (с разовым снимком цен на 27.02.2026, НЕ
живые данные): `~/Downloads/UZSE_tickers_final_27_02_2026.xlsx`. Читать
через уже готовый инструмент `shared/tools/uzse_ticker_file.py`
(`read_tickers(path)` возвращает список `TickerRow(ticker, amount, price,
SearchName, Date, Time)`).

## Фаза 0 — ОБЯЗАТЕЛЬНО ПЕРЕД КОДОМ: разведка источника данных

У нас пока НЕТ подтверждённого способа получать актуальную (не 27.02.2026)
цену акции программно. Прежде чем писать парсер:

1. Проверь официальный сайт биржи — есть сохранённая копия
   `~/Downloads/Республиканская фондовая биржа «Тошкент».mhtml`, посмотри
   на что она ссылается (домен, структуру страницы котировок).
2. Попробуй `curl` на предполагаемый домен биржи, посмотри реальный HTML —
   есть ли публичная страница с ценами по тикеру, JSON API, или нужен
   HTML-скрейпинг (по аналогии с тем как в hh-jobs скрейпили tashkent.hh.ru
   после того как выяснилось что официального API для соискателей нет).
3. Если официальный сайт биржи не отдаёт данные не-браузерным клиентам
   (как было с hh.ru → пришлось перейти на RSS) — поищи альтернативные
   источники (агрегаторы котировок УЗ рынка, если есть).
4. **Задокументируй в STATUS.md, что конкретно нашёл** — рабочий URL/метод,
   и почему он рабочий (реальный curl-запрос с реальным ответом, не
   предположение). Если за разумное время (~1-2 часа) не нашёл живой
   источник — так и напиши в STATUS.md как блокер, не выдумывай "предположим
   что API вот такое".

## Задача (Фаза 1 — MVP)

1. **`src/uzse_client.py`** — получение текущей цены для одного тикера
   (`HMKB` из `.env` START_TICKER), используя источник, найденный в Фазе 0.
2. **SQLite таблица `price_history`** (не просто "текущая цена" — временной
   ряд): `ticker, price, fetched_at`. Каждый запуск добавляет новую строку,
   не перезаписывает.
3. **`src/main.py`** — оркестрация: получить цену → записать в БД →
   уведомить в Telegram (тема "Stocks-UZ", thread_id из `.env`
   TELEGRAM_THREAD_ID=80) с текущей ценой и изменением к предыдущему
   замеру (если есть с чем сравнивать).
4. Переиспользуй `shared/db.py` и Telegram-функции по структуре
   `hh-jobs/src/responder.py` (референс, не копировать вслепую — та версия
   заточена под вакансии, здесь нужна отправка цены/тикера).
5. Прогони end-to-end реально — убедись что хотя бы одно сообщение реально
   дошло в Telegram-тему 80.
6. Обнови/создай `STATUS.md` — что нашёл в Фазе 0, что реализовано, что
   проверено вживую (не предположено).

## Что НЕ делать в этой фазе

- НЕ добавлять остальные 55 тикеров — только HMKB
- НЕ писать технический анализ (RSI/MA и т.п.) и НЕ придумывать формулы
  фундаментального скоринга — стратегия ещё не согласована с пользователем
  окончательно (см. README.md), в MVP только сбор цены + история
- НЕ писать логику "купить/продать" — бюджета нет, это чистый мониторинг
- НЕ коммитить `.env` (там реальный Telegram bot token) — проверь
  `git status` перед коммитом

## Критерий готовности MVP

- STATUS.md явно описывает найденный источник данных (или честно фиксирует
  что не нашёл — это тоже валидный результат Фазы 0)
- `python src/main.py` реально получает текущую цену HMKB (не из xlsx-снимка)
- price_history накапливает строки при повторных запусках
- Хотя бы одно реальное сообщение дошло в Telegram-тему 80
